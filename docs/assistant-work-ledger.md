# Account assistant work ledger

The desktop assistant panel and phone task panel read account RPCs instead of device directories. `useAssistantWorkTasks(ownerId,assistantId)` is the shared list/presence projection; `useTaskChatRows` reads the selected work's account history. Finished tasks survive directory removal and host sleep. The App shell installs a read-only window bridge for list/history RPCs, account events and presence. The session-page bundle obtains the owner from the self-identity bridge; its separate React root does not read shell AuthContext or create an independent authenticated data client. Existing typography, task row titles, harness and unread markers remain. An older task link with no work ID resolves only assignments matching its original assistant/executor addresses, also through account reads.

Work outcome is independent of agent presence: idle does not complete a task. Live tool/token output remains the native task viewer's optional connection and is not copied into this ledger. Cloud history failures retain existing rows, show a factual notice without a button, and retry automatically. Task lists cache by owner and assistant across mounts, retaining a refresh error alongside cached rows. Concurrent change events coalesce into one following read.

## Writes and ownership

The two backend tables are `identity.assistant_work` and `identity.assistant_work_events`. The latter is also the sole durable delivery queue. Dispatch prepares a stable empty executor seat before atomically creating work and its first event. The model starts only after durable event admission. Message, operation, child-session and work IDs survive retries. `enqueueAssistantWorkDelivery` and `enqueueAssistantWorkReport` return accepted, never delivered.

Codex114 owns the shared enqueue/claim/settle pump, reachability-aware wakeup, reconciliation and owner receipts. This branch integrates that shared code and supplies dispatch hooks, the account projections and Android native host routing. Internal replay carries the original `client_message_id` and timestamp and bypasses the ledger write hook. Old hosts lacking `assistantWork.prepare` or `assistantWork.deliver` fail explicitly.

Android and desktop/server hosts can upload their own acknowledged old receipts on natural startup/heartbeat. This is background migration, never a panel-to-device read. Original work/message IDs and occurrence time are retained; historical events are admitted facts and never reenter the delivery queue. The phone reads only actual Pi tool-call/result pairs accompanied by its durable successful send receipt, rechecks data permissions before reading and immediately before upload, and preserves native file references. Already uploaded message IDs are authoritative even when native delivery decorated the local copy. The desktop reader exposes accepted SQLite inbox receipts through the existing host bridge and checks the account's identity registration time. Missing or ambiguous evidence is skipped. SQLite filters session-direct receipts before paging and persists a per-owner scan cursor plus unresolved receipt positions; it does not copy message bodies into another queue. Phone imports isolate failures by work and checkpoint settled jobs so later heartbeats do not reopen their JSONL. No completion is inferred from model final prose or idle.

The backend closes imported waiting work older than24 hours as a coordinator inference with `LEGACY_REPORT_MISSING`; a real late executor result still prevails. Former assistant homes require owned historical provisioning/move evidence. Host failures use progress plus trusted `HOST_FAILURE`, so runtime errors do not masquerade as an executor's terminal report. The platform owner notice and real owner delivery remain separate receipts.
