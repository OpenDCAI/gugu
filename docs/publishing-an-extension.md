# 发布一个扩展到市场

> 界面上叫 App;仓库与代码里仍叫 extension。

**市场不放在数据库里**(维护者 2026-10-08)。唯一的真相是 GitHub 索引仓 `shuxueshuxue/gugu-apps`:每个 App 一个
`apps/<id>.json`,写清每一版的「仓 @ 提交 @ 目录」、包的 sha256 与字节数,以及撤回 / 停维 / 下架。
**上架 = 往索引仓提一个 PR**,只由官方合并,每一版都有人看过代码。怎么写那份 json、怎么算 sha256,见索引仓的 README。

清单必须写 `platforms: ["desktop"]`、`["phone"]` 或两者，声明人用界面适用的平台，且 `apiVersion` 至少为 11。
数组不可为空、重复或有其他值。市场先按平台筛版本，再按宿主版本挑选；安装也核对声明。
手机不运行 agent 功能，因此 `agents:*` 不影响 phone 上架，但详情会说明；手机不支持的人用能力（如 `notifications`）
与 phone 声明冲突，发布和安装会拒绝。是否真正适配手机由作者负责。已装的旧 App 不因缺这个字段而失效。

**App 的家在它自己的仓库里**(App 市场方案,维护者 2026-10-07):市场只收录「仓 @ 提交 @ 目录」打出来的那一份字节。
例:抽卡台在 `shuxueshuxue/promo-skills`。详情页和同意框据此写「代码在哪」。

**预装的只剩群文件夹(工作区),它不进市场。** 咕咕办公、全能搜索 2026-10-16 起是市场 App(索引仓 `sources/office`、
`sources/omnisearch`):老用户手里预装的那份,升级后第一次启动由 `releasePreinstalled` 改成市场来源，数据不动。
预装的 App 不会被问「有没有新版」(controller 的 `marketUpdates`):别的来源本来就顶不掉预装的那份(`extensions-service.ts` 的
`installFromDirectory`),问了只会在它身上挂一个点了就报错的「更新」。

## 从 PR 到用户手里

1. 索引仓的 CI 在 PR 上照那个提交把目录重新打一遍包,sha256 与字节数必须与 json 里写的逐字节一致;
   包里的 `manifest.json` 的 id / 版本要与 json 对上;`CHANGELOG.md` 里要有 `## <本版版本号>` 这一节
   (它就是用户在「更新到 vX」之前看到的「这版改了什么」;首版写「首次发布」也行)。
2. 合并后 CI 把包、README(图片改写成下载站地址)、图标和总目录 `index.json` 同步到下载站
   `https://download.gugu.nextmind.space/market/`。除 `index.json` 外每个文件**只写一次**,同名不同字节当场报红。
3. 客户端只读下载站(地址在 `apps/desktop/electron/updateFeeds.json` 的 `market`),❌ 直连 GitHub;
   装之前比对 sha256,对不上一个字节都不解包。

包的限制:≤ 25 MiB、≤ 2000 个文件、没有符号链接;`icon` 是 PNG(≤ 32 KiB、≤ 512px);README 里的截图是包内相对路径、每张 ≤ 1 MiB。

## 版本

和 VS Code 一样:

- **已发布的版本不可变**。同一个版本号永远对应同一份字节;要改就改 `version` 再发。索引仓的 CI 不许改旧版本那一行。
- 市场替每台机器挑「它能装的最新一版」,老咕咕拿到的是旧一点但能跑的版本。
- **发出去就自己装上**(维护者 2026-10-19):装着这个 App 的人默认自动更新到新版,不用点;新版多要了能力或去处的不自动装,
  等他点「更新」再只问新增的那几项。人自己停在旧版(装了旧版、或关了这个 App 的「自动更新」)的不跟。
- **撤回某一版**(那一行写 `yanked`):不再可装,版本号不复用;装了它的用户在设置页看到原因和更新按钮,
  扩展照常能用——撤回是告知,不是远程禁用。
- **停止维护**(`deprecated`):划掉、不再推荐,可指替代扩展;❌ 自动卸载、❌ 自动迁移。
- **下架**(`unlisted`):整个从目录里拿掉;已装的人收不到更新,他的 App 页那一行写「市场中已没有此 App，不再提供更新」(照常能用,❌ 卸载)。
