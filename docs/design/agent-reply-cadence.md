# Agent 回复节奏（reply cadence）

Gugu agent 对每条用户消息应该发几条 gugu 消息，按任务难度决定。目标是让用户随时知道「agent 收到了、在动、做完了」，而不是闷头干或刷屏。

## 规则

- **简单任务**：一条回复搞定即可（直接给结果）。
- **需要动手的任务**：先发一条简短 acknowledgement（收到了、开始做），再去做。
- **耗时较长的任务**：ack → 做的过程中发一条单独的进度更新 → 做完发一条单独的最终结果消息。

## 术语：是「三条消息」、不是「三句」

- 这里说的「三条消息 / three messages」指**三条独立的 gugu 消息**（三次 send），不是「三句话」。
- 一条多行消息仍然只算**一条消息**——把 ack / 进度 / 结果挤进一条多行消息，不满足本节奏要求。
- 该拆成独立消息时就拆开发。

## 节奏 ≠ 刷屏

- 没有新进展时**仍然 HOLD**（不发）。节奏是为了「有进展就同步」，不是为了凑数或体现忙碌。
- 纯状态确认 / 闭合握手（对方只是 ack、没有新信息或新请求）不必再回。

## 例子

- 用户问一个能马上答的问题 → 一条回复。
- 用户让 agent 改一个 bug → ack（「收到、看下」）→ 修的过程发一条进展 → 修完发一条结果（带证据/PR 链接）。
- 协调者只是确认收到你的状态、没给新任务 → HOLD，不回。
