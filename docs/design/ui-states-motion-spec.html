咕咕 UI 状态与动效规范

v0 评审稿 · 2026-07-23

统一全产品的交互状态与动效。产品有两侧：gugu 自绘组件（tokens.css），和任务页——它实为 Base UI 1.3 + 两套皮肤（vanilla-extract 设计系统 + shadcn 形的 Tailwind 层），并无 Radix/shadcn 本体。本页所有样例是活的——可以 hover、按住、点选、回放。规范经你点头后落盘仓库并开始迁移。

1五条原则

  1. 状态是语法，不是装饰。每个可交互元素必须回答六态：rest / hover / press / selected(如适用) / focus-visible / disabled(如适用)。缺态 = bug，和缺 loading/empty 同级。
  2. 状态一律 CSS。伪类（:hover/:active）或 data 属性（data-selected/data-on）。❌ onMouseEnter+useState、❌ e.currentTarget.style 命令式改 DOM——这两类是现状最大的分裂源（13+22 处）。
  3. 色值、时长、easing 全走 token。❌ 魔数（0.2s / 120ms / ease / linear）、❌ transition: all。
  4. 中性外壳。状态反馈只用中性叠色与透明度（hover 6% → press 10% → selected 12%），不引入新色相；唯一例外是危险项的 --danger-tint。（对应 design-lessons L2/L4：专业感来自做减法。）
  5. 有入必有出。浮层入场/出场成对；宽高变化必须过渡；prefers-reduced-motion 全局降级（本页已带）。

动效禁则

  1. ❌ transition: all —— 指明属性（background / color / opacity / transform / width）。
  2. ❌ 魔数时长/easing —— Tailwind 侧只允许 duration-[var(--dur-fast)] 等 token 形式。
  3. ❌ 自造 keyframe —— 先查 §4 场景表和既有 keyframes（gg-menu-pop / gg-sheet-* / running-shimmer / skeleton-shimmer / spin），确实没有再新增并登记进规范。
  4. reduced-motion 必须尊重 —— tokens.css 加全局降级（本页样式表末行即范本）。

5实现机制

规范落地 = 一段 CSS + 两条 React 约定 + 一张会话页皮肤映射表。本页 §3 的样例就是跑在这段 CSS 上。

5.1 tokens.css 追加（拷贝即用）

/* 动效 token */
--ease: cubic-bezier(.2,.8,.2,1);
--ease-spring: cubic-bezier(.22,1,.36,1);
--ease-pop: cubic-bezier(.16,1,.3,1);
--dur-fast: 120ms;  --dur-med: 180ms;  --dur-slow: 260ms;
/* 存量三件套改为别名 → 旧引用自动升级 */
--transition-fast: var(--dur-fast) var(--ease);
--transition-normal: var(--dur-med) var(--ease);
--transition-slow: var(--dur-slow) var(--ease);
/* 状态补缺 */
--danger: #ef4444;  --danger-tint: #ef44441a;   /* light: #ef444414 */
/* 焦点环全废(维护者拍板 07-24「任何情况都无环」) */
*:focus, *:focus-visible { outline: none; }
/* 收敛别名（值不变，指向归一） */
--chat-row-hover: var(--hover);  --menu-item-hover: var(--hover);
--accent-tint-row: var(--selected);  --chat-row-active: var(--selected);
--menu-danger: var(--danger);

/* 原型类 .gg-row / .gg-ghost / .gg-fill / .gg-seg / .gg-mi /
   .gg-danger-item / .gg-input / .gg-reveal —— 全文见本页源码 <style> 第二段，
   连同触屏 .gg-pressable 合并为「交互状态」一节 */

/* iteration-count 必须配对压 1:只压时长的话 infinite 动画会高频闪烁,比不降级更糟 */
@media (prefers-reduced-motion: reduce){
  *{animation-duration:.01ms!important;animation-iteration-count:1!important;
    transition-duration:.01ms!important;scroll-behavior:auto!important}
}

5.3 会话页（Base UI）侧：三件事

① 皮肤桥收口（最重要）。桥（EmdashTaskFrame 的 GUGU_SKIN_BRIDGE_CSS）现在自造 color-mix 92%/85% 合成 hover/selected；改为按 gugu 阶梯合成，两侧视觉从此同源：

/* 皮肤桥内，X = 各 surface 基色；比例即 gugu 状态阶梯 */
--em-surface-X-hover:    color-mix(in srgb, X, var(--fg) 4%);   /* ≈ --hover 6% 视觉档 */
--em-surface-X-selected: color-mix(in srgb, X, var(--fg) 8%);   /* ≈ --selected 12% 视觉档 */
/* 动效 token 一并注入桥：--ease / --dur-fast / --dur-med / --dur-slow */

② 状态语义 ↔ Base UI data 属性对照。会话页新代码按此表挂状态（B 层 Tailwind variant / A 层 vanilla-extract selector 同一语义）：

③ 清死类。B 层残留的 hover:bg-muted / focus:bg-accent 等 shadcn 语义类在会话页的 @theme 里根本未定义（0 规则生成），逐个换成真实背景梯队 token——同一菜单里 item 走真类、subtrigger 走死类的隐性不一致即源于此。

方向说明：会话页的出场范式（data-closed + animate-out）比 gugu 侧健康，gugu 的 ui/Menu、ui/Sheet 出场实现向它看齐；反过来，状态 token 化（--hover/--selected/--press 阶梯）以 gugu 为准、经皮肤桥供给会话页。两侧各取所长。
