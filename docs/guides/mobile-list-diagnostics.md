# Mobile Messages list diagnostics

This instrumentation investigates two unproven causes in #1892: the whole Messages root going blank after Back, and a single Agent row disappearing. It changes no list selection, filtering, routing, network state or recovery behavior. The two symptoms are not assumed to share a cause.

The renderer keeps at most 80 metadata observations in memory and emits at most 60 per minute through the existing `mobile/list-diagnostics` renderer logger. Suppressed observations are counted, and at most 80 asynchronous emissions may be pending. Android's checked-in Capacitor configuration disables native bridge logging; do not assume the console fallback is available in logcat. The supported phone collection path is the in-memory snapshot, included as `mobile_list_diagnostics` only when the person explicitly submits the existing problem-feedback form. There is no separate file-export button, new request, storage file or automatic upload. App restart, logout or account replacement clears the in-memory observations.

| Event | Trigger | Recorded facts |
| --- | --- | --- |
| `shell` | 250 ms after a navigation state change, or after scrolling/clicking/resizing settles; visibility/page-show events sample immediately | Active/root tab enums, list/detail mode, hidden/layer/tab-bar flags, foreground and network booleans, viewport dimensions, pager offset/width, shell/list-pane/list/My-button rectangles and display/visibility/content-visibility/inert values. Missing elements are explicitly null. |
| `rows` | The mobile Messages list's existing render inputs change | Input/rendered counts, loading flag, additions/losses/changed flags for at most 12 rows, total changed count. Flags distinguish source loss from filtering and show ownership, search match, activity presence before/after native projection, selection and draft presence. Unchanged observations are deduplicated. |
| `row-open` | A normal click on an existing `data-chat-row` element | A keyed row digest correlates entry with later list observations. No event is consumed or navigation initiated. |

Row correlation uses full HMAC-SHA-256 hex digests and a fresh, non-extractable random key for each signed-in shell lifetime. The key stays only in memory, is never exported, and is replaced on account change/logout. The same raw ID therefore has unrelated digests on different devices or app lifetimes; exported digests cannot be tested against guessed IDs without that secret key. At most 2,048 digests are cached, after which correlation is null; unavailable cryptography also yields null, never an unhashed fallback or an error message. Late hashing results from a previous owner are discarded. Row losses are placed before additions in a truncated refresh. The output contains no message/preview text, titles, search text, draft text, email, URL, token or raw account/chat/Agent/device ID. The account ID is used only to clear the previous owner's memory, and is never emitted. CSS values are reduced to fixed status codes, not arbitrary strings. A snapshot is copied before export so readers cannot alter the retained evidence.

The digests cannot be joined to server-side chat IDs. They only show that the same row changed within one run. Flags such as `kind`, `owned` and `imActivity` characterize the affected row; they do not uniquely identify an Agent. The current feedback form explains that diagnostics are attached, but does not show this structured snapshot before submission. This change does not add a preview UI; maintainers must decide separately whether one is required.

When the problem recurs, submit feedback before logging out or restarting. Match its timestamps and keyed row digest to the normal Back or row-open sequence. A missing source row, a present-but-filtered row and a zero/hidden/off-page root are different observations, not root-cause verdicts. The trailing 250 ms samples describe settled layout; they do not establish the exact start or duration of a transient blank frame. Instrumentation is bounded and may suppress a busy burst; the count must be considered when interpreting gaps.
