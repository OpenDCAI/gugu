# Local renderer diagnostics

Desktop renderers record a small, content-free diagnostic stream through the existing local IPC bridge. The main process adds the actual renderer process ID and webContents ID. A random page ID distinguishes page lifetimes and reloads.

The file is `gugu-ui-diagnostics.log` next to the current account's `gugu-main.log`. It rotates at 1 MiB with two backups. It is separate from normal console output and `feedback:log-tail`, and has no upload or network path. No message bodies, search text, input values, dialog titles, account identifiers, URL queries or arbitrary error objects are accepted. The main-process boundary enforces the field allowlist again.

- Long tasks strictly above 200 ms record their start time, duration, frame attribution and the overlay stack observed when the browser delivers the entry. The browser does **not** provide a JavaScript component/call stack for long tasks. Missing or external attribution is `unknown`; it is not inferred from the active dialog. Unsupported observation is recorded in the start event.
- A memory observation is requested at startup and every five minutes. JS heap estimates and the main process's native working-set/peak-working-set bytes are separate fields. DOM element counts include registered embedded shadow roots. Timers and observer delivery can be delayed by a blocked renderer; timestamps describe actual observations. Several webContents may share one process/isolate, so their memory values must not be summed.
- Dialog/popover/menu lifecycle observations contain numeric layer IDs and bounded stacks, including closed-but-retained layers and inert ancestry. Root registration covers the main document and embedded app shadow roots. Ordinary mutations inspect only added subtrees; an oversized batch schedules one coalesced rescan of registered roots. No synchronous layout measurements are made.
- Escape records browser-event-to-capture delay, trusted/composing flags, whether bubbling was observed, default prevention, layer stacks before/after the dispatch task and a content-free focus tag. App/session dialog and popover callbacks identify their handler family. Session modal close guards are recorded separately from actual closure. Untagged handlers remain `unknown`; a close request is not proof that the dialog closed. Browser timestamps are not hardware latency measurements. Other keys are not observed.

Open/close requests include only first-party source locations from a bounded call stack. Function names, private filesystem paths and external frame names are omitted. Callback return values, cancellation, focus and event propagation are not changed. Observer, timer and logging failures do not reject UI callbacks.

The renderer permits up to ten long-task entries and fifty other records per minute, with memory observations outside that event budget. A subsequent record reports suppressed counts. The IPC sink independently caps other records at sixty per renderer per minute and native memory reads at one per five minutes. It reports its own suppression count after the window turns over. These limits are diagnostic gaps, not evidence that no event occurred. Collection is disposed on page exit and development module replacement.
