# cache 保温器

会话闲着的时候,它的提示缓存在最后一次请求之后的 TTL 内还是热的。订阅账号实测这个 TTL 是 1 小时。
- 热着再用一轮,上下文按 0.1 倍读回；
- 凉了再用,要按约 1.9 倍把整份上下文重写一遍。

保温器在缓存快凉的时候,替你勾上的会话发一轮最便宜的 ping（「什么都不用做,只输出 [NO_REPLY]」),缓存就续上了。

## 怎么用

1. 打开工作区面板里的「保温器」tab,在要保温的会话前面打勾。
2. 就这些。钟在后台页里走,tab 关着也在走。

面板上每个会话显示这几项:
- 状态；
- 缓存还热多久；
- 上下文多大；
- ping 过几次；
- 真用上的时候估计省下了多少。

上下文越大的会话越值得保温。

## 它什么时候不 ping

- 会话在跑、在等人、或者报错了。
- 缓存已经凉了。这时候再 ping 本身就是一次冷启动,不划算；等这个会话下次真用过,再接着保温。
- 保温器还没亲眼看到它跑完一轮的会话(比如装上之前就闲着的),不知道它凉没凉,也不 ping;等它下次真用过,再接着保温。
- 一次只 ping 一个会话,等它跑完再 ping 下一个。被收掉进程的会话会被拉起来,不会一下子在你机器上起一串引擎。
- **退让**：
  - 任何一个开着的面板会话报「账号额度快满了」或「用完了」,就一直停到它说的重置时刻;
  - ping 失败了,或者 ping 之后会话报错,所有 ping 停 30 分钟。

## 报错停下的会话

额度一重置,保温器自己把打了勾、又停在报错上的会话排成队,每隔 2 分钟续上一个;「依次续上报错的会话」按钮也是这个队。
- 为什么要排队:额度一恢复,一群会话同时醒来,会在同一分钟里各自把上下文整份重写一遍。
- 续上的会话要是又报错,说明额度还没恢复,队伍就停下来。

## 什么会话值得保温

- 走你自己订阅账号的会话(缓存 1 小时)值得保温:闲 1–17 小时之内再用,都比凉了再用便宜。
- 走咕咕平台模型的会话缓存只有 5 分钟,每 5 分钟 ping 一次反而更贵,别给它们打勾。

## 权限

- `agents:read:all`：看这台机器上所有会话的状态、上下文大小和引擎报的账号额度。
- `agents:control:all`：给你勾上的会话发 ping、续上报错的会话。和 agent 之间的 `session_message` 走同一条路:只进那条会话,标着「来自 cache 保温器」,不往任何聊天里写。
